# Підготовка до захисту практичної 6

Exchange серіалізує та перевіряє CSV/JSON; Room залишається джерелом стану для списків і аналітики. Storage Access Framework надає доступ до обраного файла без повного доступу до накопичувача. Копія зберігається у filesDir, перевіряються MIME й обмеження розміру. PDF переглядається через PdfRenderer, DOCX має текстовий попередній перегляд із word/document.xml. PdfDocument генерує багатосторінковий звіт. ResourceSampler рахує CPU саме процесу, PSS та батарею. Release збирається із R8 і підписується локальним ключем, який не потрапляє до GitHub.

## Демонстрація

1. Додай запис, запиши CSV/JSON, прочитай назад, перевір список і фільтр періоду.
2. Вибери пост, прикріпи фото/PDF/DOCX, зміни назву й відкрий перегляд.
3. Створи PDF, експортуй його; поясни тест із 45 рядками й трьома сторінками.
4. Покажи тести, звіт покриття, відмінність debug/release і метадані публікації.
5. Відкрий презентацію та поясни схему UI → ViewModel → Repository → Room/API.

## Можливі питання

### Навіщо лапки у CSV?

Поле може містити кому, лапки чи перенос. Лапки всередині подвоюються; роздільники поза quoted fields відділяють колонки.

### Чому JSON теж треба перевіряти?

Синтаксично правильний JSON може містити дублікати id, від’ємні числа або неправильні координати. Серіалізація не замінює доменну валідацію.

### Чому файлові операції в Dispatchers.IO?

Читання, запис і генерація PDF можуть блокувати потік. Їх не слід виконувати на головному потоці інтерфейсу.

### Чи DOCX показується як у Word?

Ні. Реалізовано текстовий попередній перегляд, без повної верстки Word. PDF має растровий перегляд сторінок.

### Що означає CPU 150%?

Метрика нормована на одне ядро: використання кількох ядер може перевищувати 100%. Це не відсоток навантаження всього пристрою.

### Що перевіряють unit, integration та UI тести?

Unit — чисті функції; integration — взаємодію з HTTP/Room; UI — введення, навігацію й доступність дій. Один тип не замінює інші.

### Чи 100% покриття гарантує правильність?

Ні. Покриття показує виконані рядки/гілки, але не якість очікувань і не повноту сценаріїв. Важливі негативні випадки та коректні assertions.

### APK і AAB — різниця?

APK можна встановити на пристрій. AAB — пакет для поширення, з якого магазин формує потрібні APK. Підготовка AAB не означає публікацію у Play.

### Що роблять R8 та ключ підпису?

R8 скорочує й оптимізує код та може перейменовувати класи. Підпис ідентифікує автора оновлень; ключ треба зберігати приватно. Для Gson потрібні правила збереження DTO.

### Що ще потрібно для Google Play?

Акаунт розробника, актуальні декларації Play Console, політика конфіденційності, графіка, рейтинг і перевірка вимог магазину. Збірка та метадані підготовлені, публікацію не виконано.

## Вправа

Експортуй файл із назвою поста, що містить кому й лапки. Перед імпортом передбач точний результат, потім перевір його тестом.
